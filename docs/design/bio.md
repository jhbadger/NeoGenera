# Bioinformatics (Phase 9)

Phase 9 is a Lisp library (`lisp/bio/`) plus one C file, `src/prims_bio.c`, with the two kernels that were too slow in the VM.

## Layout

| File | Contents |
|---|---|
| `00-seq.lisp` | `bioseq`, complement/translate/GC, 2/4/5-bit packed sequences, genetic codes 1/2/4/5/11, k-mers, ORFs, distances, protein properties |
| `10-formats.lisp` | FASTA, FASTQ, GenBank (features and locations), GFF3/GTF, BED, VCF, SAM, BAM; gzip through the system `gzip` |
| `20-align.lisp` | scoring matrices (BLOSUM62, PAM250, nucleotide), `align` (affine gaps, global/local/semi-global, banded), suffix-array search, k-mer index and seeded search, IUPAC motifs, PWMs, a regex engine |
| `30-phylo.lisp` | distance models, UPGMA, neighbor joining, Newick, text trees, Robinson-Foulds, interval tree and interval arithmetic |
| `40-external.lisp` | safe subprocess layer, BLAST tabular / PAF / samtools parsers |
| `50-present.lisp` | sequence, alignment, tree and feature viewers with clickable residues, columns and clades |
| `60-workflows.lisp` | genome annotation, proteome search, variant summary, read QC, primer design, enrichment |

## Kernels in C

`%DP-ALIGN` fills a Gotoh three-state matrix (M, X, Y) for global, local and semi-global alignment. It keeps three score rows and a
byte matrix of traceback pointers (two bits per state), and returns the score, the end cell and the pointer matrix; the traceback is Lisp.
Gap cost is `open + (k-1) * extend`; a band restricts the cells computed. `%SUFFIX-ARRAY` builds a suffix array by prefix doubling with `qsort`.
Both are checked against independent implementations in the test suite: a Lisp Gotoh dynamic program (72 random cases across modes and gap
settings plus protein cases) and a naive suffix sort.

## Design decisions

* **Coordinates are zero-based and half-open everywhere** in the objects, whatever the file format; converters live in the parsers.
* **No shell, ever.** `run-tool` validates the program name, requires string arguments and uses `execvp`; there is no string-to-shell path.
  BLAST, minimap2 and samtools are called through it and their text output parsed into structures.
* **BAM is read by decompressing with `gzip -dc`** (BGZF is a series of gzip members) and decoding the binary records in Lisp; the test fixture is
  generated by `tests/data/make_fixtures.py` and the BAM and SAM parsers are checked against each other.
* **Presentations are layered.** Structures are presented under their own type names, so any returned value is clickable; viewers add `residue`,
  `alignment-column` and `clade` types for finer clicks. Without a window system the viewers print text.
* **Statistics reuse.** Enrichment uses Phase 8's Fisher test and p-value adjustment; sequence distances use the matrix and RNG code for tests and simulations.

## Validation

`tests/lisp/bio-tests.lisp` uses published examples (Wikipedia's Needleman-Wunsch and Smith-Waterman examples, the standard genetic code example,
the NCBI genetic code tables for the differences tested), property checks (self-alignment scores equal the sum of the matrix diagonal; the rescored
alignment equals the reported score; BLOSUM62 and PAM250 are symmetric with known diagonals), simulated data (planted genes on both strands in a
random genome must all be found with exact coordinates and proteins; a diverged protein must find its source; neighbor joining on additive
distances recovers the tree exactly; simulated lineages recover their topology), and format fixtures cross-checked between SAM and BAM.

## Deviations from the roadmap

* No real genome ships with the repository (no network access when this phase was written); the genome-scale exit criterion is exercised on
  synthetic genomes with planted genes, and the benchmark numbers are from published worked examples rather than from NCBI datasets.
* Alignment is Lisp plus a C fill for pairwise DP only; multiple alignment, profile search and the suffix-array LCP structures are not implemented.
  Full-matrix alignment memory is `(n+1)(m+1)` bytes, so long alignments need `:band`.
* BAM is read-only and ignores the index; `B`-array tags are skipped. CRAM is not supported.
* GenBank parsing covers LOCUS, DEFINITION, ACCESSION, ORGANISM, FEATURES (including joins and complements) and ORIGIN; other header lines are ignored.
* The k-mer index stores positions in hash tables, which is practical to a few megabases; the packed representations are for storage and are not used by the index.
