# Hardening and the 1.0 release (Phase 10)

## Performance pass

`bench/bench.lisp` (`make bench`) times representative workloads. The method was: run everything once, look at the outliers, profile them, fix the cause.
The bytecode VM itself was never the bottleneck (`fib 27` takes 0.07 s, `tak` 0.14 s, 200k hash-table inserts 0.27 s), so native code generation was not undertaken.

| Workload | Before | After | Cause and fix |
|---|---|---|---|
| `lm` on 3000 x 4 | did not finish (ran out of heap) | 0.10 s | the Householder QR formed the full m x m matrix Q; least squares now reduces the right-hand side as it goes and never forms Q (O(mn) memory) |
| reverse-complement of 1 Mbp | 1.12 s | 0.001 s | per-character Lisp loop replaced by the C kernel `%string-translate` / `%string-reverse` |
| translate 1 Mbp | 1.16 s | < 0.001 s | `%translate-codons` in C |
| GC content of 1 Mbp | 0.34 s | 0.001 s | `%count-chars` in C |
| find-orfs, 300 kbp, both strands | 3.00 s | 0.03 s | `%orf-scan` in C finds the open frames, Lisp builds the objects |
| FASTA write and read, 1 Mbp | 1.39 s | 0.09 s | alphabet detection used `find` per character; `%string-all-in` in C |
| documentation search x 200 | 1.41 s | 0.10 s | per-entry term tables replaced by one inverted index with a sorted vocabulary for prefix matching |
| SVD 60 x 60 | 1.45 s | 0.69 s | one-sided Jacobi on column vectors instead of element-wise `mref` |
| alignment 1500 x 1500, suffix array 1 Mbp | 0.02 s, 0.25 s | unchanged | already C kernels |

## Memory and stability

* **Crash-safe images.** `--save-image` writes `FILE.tmp.<pid>`, `fsync`s, and renames over the target; a failed save leaves the old image untouched. The image
  header gained a payload checksum (FNV-1a) verified before the live heap is overwritten, and range checks (format `NGIMG004`). Tests corrupt, truncate and replace images.
* **Out of memory and out of stack are errors, not crashes.** Allocation compares sizes before any pointer arithmetic and signals a Lisp error; a 4 MB reserve
  at the end of each semispace lets error handling run, and is closed again by the next collection. The evaluator's protected-object stack is bounds checked; the VM frame, value
  and root stacks have reserves that open on overflow and close when the error is handled; and a C stack-address guard protects the recursive kernel code (evaluator, VM calls, reader, printer, `equal`).
  Before this, `(defun f (n) (+ 1 (f (+ n 1))))` killed the process.
* **Soak test.** `tests/soak/soak.lisp` runs a mixed workload (lists, strings, hash tables, bignums, CLOS, conditions, file formats, alignment, trees, regressions, subprocesses,
  the compiler) and compares the live heap early and late in the run. Twenty seconds show 355 rounds, 70 collections and a flat 6.9 MB live heap; `NG_SOAK_SECONDS=3600 make soak` is the long form.
* **GC tuning.** The collector is generational (an 8 MB nursery over a two-space old generation) with triggers below the limits; no tuning was needed for the soak workload.

## Reproducible builds and packaging

* The image no longer records the build directory (`*source-root*` is found at run time from `NG_SOURCE_ROOT`, which the `bin/neogenera` wrapper sets), and the binary is compiled with `-ffile-prefix-map`;
  `make repro-check` builds in two different directories and requires identical images and binaries.
* `make install` lays out `bin/`, `lib/neogenera/{neogenera,neogenera.img}`, `share/neogenera` (sources, manuals, examples), `share/doc/neogenera/html` and a man page. `make dist` makes a deterministic tarball
  (sorted names, fixed owner and mtime) with `SHA256SUMS`; `make deb` builds a Debian package; `Dockerfile` is a two-stage build; `packaging/homebrew/neogenera.rb` is a formula.

## Quality gates added

`tests/lisp/fuzz-tests.lisp`, `tests/lisp/hardening-tests.lisp` (image integrity, subprocess I/O, allocation limits, string kernels, stack safety, regressions), `tests/conformance` (about 600 cases),
`tests/soak`, `bench/`, and `examples/run-all.sh` (ten programs that must run and print what they claim). The example gallery and the fuzzers found real bugs that the earlier suites missed:
`loop` with several `collect` clauses, `format ~@[`, a BAM allocation bomb, the subprocess deadlock and the recursion crash.

## Security and compatibility

`docs/SECURITY.md` records the review and `docs/COMPATIBILITY.md` lists the deliberate deviations from ANSI Common Lisp; `docs/CONFORMANCE.md` is generated by `make conformance`.

## Release checklist

1. `make release-check` (tests, ASan/UBSan fuzz run in CI, reproducibility) and `make conformance`.
2. Update `CHANGELOG.md`, `*ng-version*` in `lisp/core/60-listener.lisp`, the Homebrew formula URL and checksum.
3. `make dist deb docs site`; sign `SHA256SUMS`; tag `v<version>`; publish the tarball, package and site; post the announcement (`docs/RELEASE-1.0.md`).
